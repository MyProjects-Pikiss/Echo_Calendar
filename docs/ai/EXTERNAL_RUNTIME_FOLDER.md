# Echo Calendar External Runtime Folder

Echo Calendar keeps secrets and runtime data outside this git repository.
The expected Windows location is:

```text
%USERPROFILE%\Echo_Calendar
```

AI sessions may not be able to read this folder directly. Use this document
as the contract for what should exist there and how the repo refers to it.

## Folder Layout

```text
%USERPROFILE%\Echo_Calendar\
  secrets\
    backend.env
    app-signing.env
    release-key.jks
  cloudflared\
    config.yml
    <tunnel-id>.json
    cert.pem
  data\
    usage.db
    usage.db-shm
    usage.db-wal
    holiday_cache.db
  downloads\
    echo_calendar.apk
    app_version.env
```

## What Each Folder Contains

- `secrets/backend.env`: real backend secrets only. It should contain values
  such as `OPENAI_API_KEY`, `KOREA_HOLIDAY_API_KEY`,
  `USAGE_DASHBOARD_ACCESS_KEY`, and admin credentials. Public runtime defaults
  belong in `config/echo-calendar.config.env`. Do not commit this file.
- `secrets/app-signing.env`: Android release signing properties. Its
  `storeFile` should point to
  `%USERPROFILE%\Echo_Calendar\secrets\release-key.jks`.
- `secrets/release-key.jks`: Android release signing key. Do not commit this file.
- `cloudflared/config.yml`: Cloudflare Tunnel config. In Docker it must use a
  container path for credentials, for example
  `/etc/cloudflared/<tunnel-id>.json`.
- `cloudflared/<tunnel-id>.json`: Cloudflare Tunnel credentials. Do not commit
  this file.
- `cloudflared/cert.pem`: Cloudflare account certificate. Useful for tunnel
  management commands. Do not commit this file.
- `data/usage.db`: operational SQLite DB for users, sessions, and usage events.
- `data/usage.db-shm` and `data/usage.db-wal`: SQLite WAL companion files for
  `usage.db`. Move or back up these together with `usage.db`.
- `data/holiday_cache.db`: holiday cache DB. It can be regenerated by holiday
  sync if the holiday API key is available, but keeping it avoids a fresh sync.
- `downloads/echo_calendar.apk`: APK served by the backend download endpoint.
- `downloads/app_version.env`: runtime app version file generated by
  `config/scripts/sync_config.py`.

## Repo References

The source config is:

```text
config/echo-calendar.config.env
```

It should point to the external folder like this:

```env
BACKEND_EXTERNAL_ENV_PATH=%USERPROFILE%\Echo_Calendar\secrets\backend.env
CLOUDFLARED_DIR=%USERPROFILE%\Echo_Calendar\cloudflared
APP_SIGNING_CONFIG_PATH=%USERPROFILE%\Echo_Calendar\secrets\app-signing.env
BACKEND_DATA_DIR=%USERPROFILE%\Echo_Calendar\data
BACKEND_DOWNLOADS_DIR=%USERPROFILE%\Echo_Calendar\downloads
```

Generated files:

- `server/.env` contains Docker Compose paths expanded for the local machine.
- `app/APP_SIGNING_PATH.txt` points Gradle to the external signing env file.
- `config/scripts/sync_config.py` writes `app_version.env` into the external downloads
  folder, not into `server/downloads`.
- `server/docker-compose.yml` bind-mounts external `data`, `downloads`, and
  `cloudflared` folders into the containers.

## Important Rules

- The external folder is the source of truth for runtime data, secrets, tunnel
  credentials, and APK delivery files.
- The repo should not contain `server/backend/data` or `server/downloads`
  runtime copies.
- Stop Docker containers before copying or backing up SQLite DB files.
- Treat `usage.db`, `usage.db-shm`, and `usage.db-wal` as one set.
- Never commit real `.env`, `.jks`, tunnel JSON, `cert.pem`, DB, APK, or log
  files.
